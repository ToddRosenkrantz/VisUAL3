Assembly language guide

ARMv7 (A32) code in GNU assembler syntax, as written for gcc, clang and Linux. The emulated core is a Cortex-A7-class ARMv7-A processor with a VFPv4 floating-point unit (32 double registers).

A first program

@ add up the words in table
        .text
_start: ldr     r0, =table      @ address of the data
        mov     r1, #4          @ number of words
        mov     r2, #0
1:      ldr     r3, [r0], #4  @ load, then step to the next word
        add     r2, r2, r3
        subs    r1, r1, #1
        bne     1b             @ back to the local label 1:
        bx      lr             @ finished

        .data
table:  .word   10, 20, 30, -5
  • Execution starts at the first instruction in .text.
  • The program ends when execution runs past the last instruction, or when it returns with bx lr, mov pc, lr or pop {…, pc}: LR starts at a return address that stops the run.
  • SP starts at 0xFF000000. The stack is full-descending: push stores below SP.
  • Data in .data, .rodata and .bss is placed after the code. Uninitialised memory reads as zero.

Labels and comments

  • A label ends with a colon: loop:. It may share a line with an instruction, stand on its own line, or several labels may mark the same place. Names use letters, digits, _, . and $, and cannot start with a digit. Labels are case-sensitive.
  • Numeric local labels can be reused: 1: is referred to as 1b (the previous 1:) or 1f (the next one).
  • Comments: @ … or // … to the end of the line, /* … */ across lines, and a line starting with #.
  • ; separates two statements on one line. It does not start a comment.
  • Mnemonics, registers and directives can be written in any case.

  • Add s to set the flags: adds, movs. Compares always set them. muls and mlas set N and Z only; umulls and the other long multiplies set N and Z from the 64-bit result. movw, movt, mls, sdiv, udiv, the extends, the bit-field instructions, clz, rbit, the rev family and nop have no s form.
  • A bit field is #width bits starting at bit #lsb, with lsb + width at most 32: ubfx r0, r1, #8, #8 takes bits 8–15 of r1. bfi and bfc change only the field and leave the other bits of Rd alone.
  • sdiv and udiv round toward zero, as C does. As on the Cortex-A7, dividing by zero gives 0 rather than an error, so test for a zero divisor first if it matters.
  • Any 32-bit constant can be built with movw then movt: movw r0, #:lower16:table and movt r0, #:upper16:table load an address, as gcc does. Like GNU as, mov r0, #0x1234 becomes movw when the value fits in 16 bits but is not an ARM immediate.
  • The long multiplies write the low word to the first register and the high word to the second: umull lo, hi, r2, r3. The extends can rotate first: uxtb r0, r1, ror #8 takes byte 1.
  • Add a condition code to run an instruction only when it holds: addeq, bne, bxle lr. The s comes before the condition: subsgt.
  • The destination may be left out when it is the first source: add r0, #1 means add r0, r0, #1.
  • ldm/stm take a mode: ia (the default), ib, da, db, or the stack names fd, ed, fa, ea. push {list} is stmdb sp!, {list} and pop {list} is ldmia sp!, {list}. The lowest-numbered register always uses the lowest address.

Loads and stores

AddressMeaning
[r1]The address in r1.
[r1, #8]r1 + 8. r1 is unchanged.
[r1, #8]!r1 + 8, then r1 is set to that address.
[r1], #8r1, then r1 is increased by 8.
[r1, r2]r1 + r2.
[r1, -r2]r1 − r2. A register offset can be subtracted; +r2 is also accepted.
[r1, r2, lsl #2]r1 + r2 × 4: element r2 of a word array. The shift can be lsl #0–31, lsr #1–32, asr #1–32, ror #1–31 or rrx.
=valueldr r0, =0x12345678 or ldr r0, =label loads any 32-bit value.

An immediate offset can be any value from −4095 to 4095. As on ARMv7 Linux, ldr, str, ldrh, ldrsh and strh work at any address: an unaligned access reads or writes the bytes in little-endian order and takes one extra cycle. With Strict alignment turned on in Edit → Preferences, an unaligned word or halfword access stops the run instead, as on a core that traps alignment faults. ldm, stm, push and pop always need a word-aligned address.

Bytes and halfwords

InstructionDoes
ldrb / ldrhLoad a byte / halfword and fill the upper bits with zeros (unsigned).
ldrsb / ldrshLoad a byte / halfword and copy its top bit into the upper bits (signed): 0xFF loads as −1.
strb / strhStore the low byte / halfword of the register. There is no signed store.

ldrh, strh, ldrsb and ldrsh take a smaller set of addresses than ldr and ldrb: an immediate offset from −255 to 255, or a register offset with no shift ([r1, r2] or [r1, -r2], not [r1, r2, lsl #1]). Pre- and post-indexing work as usual.

ldrd and strd load or store two words: the first register gets the word at the address and the second gets the word after it. The registers must be an even/odd pair other than lr (r0/r1, r2/r3, … r10/r11); the second may be left out: ldrd r4, [r0] means ldrd r4, r5, [r0]. They take the same addresses as ldrh, and always need a word-aligned address. strd r4, r5, [sp, #-8]! saves a pair on the stack.

Expressions

Constants, offsets and data values can be expressions of labels and numbers: mov r0, #(1 << 4) - 1, .word end - start.

  • Numbers: decimal 42, hex 0x2a, binary 0b101010, octal with a leading zero (052), characters 'A' and '\n'.
  • Operators, tightest first: - ~ (unary); * / % << >>; | & ^; + -. Use brackets when in doubt.

Floating point (VFP)

Help → Load floating-point example opens five small functions (dot product, average, scale in place, hypotenuse, rounding) with ready-made C Call cases and expected results. One case is meant to fail: it shows x*x overflowing to infinity.

The floating-point unit has its own registers, shown on the VFP tab: 32 single-precision registers s0–s31 and 32 double-precision registers d0–d31. They overlap: d0 is s0 (low half) and s1 (high half), up to d15 = s30, s31. d16–d31 are separate.

@ C: extern double average(const double *a, int n);
        .global average
average:
        vmov    s15, r1         @ n into a VFP register
        vcvt.f64.s32 d16, s15  @ ... converted to double
        vsub.f64 d0, d0, d0    @ sum = 0.0
1:      vldmia  r0!, {d1}       @ load a[i], step r0 by 8
        vadd.f64 d0, d0, d1
        subs    r1, r1, #1
        bne     1b
        vdiv.f64 d0, d0, d16   @ result in d0
        bx      lr

Arithmeticvadd vsub vmul vdiv vnmul vabs vneg vsqrtvmul.f32 s0, s1, s2

  • Each instruction names its type: .f32 for single precision on s registers, .f64 for double precision on d registers. Conditions go before the type: vaddeq.f32.
  • vmov copies between registers of the same kind (vmov.f64 d0, d1) and between core and VFP registers: vmov s0, r0, vmov r0, s0, vmov d0, r0, r1 (r0 is the low half), vmov r0, r1, d0, vmov.32 d0[1], r2. It copies bits: use vcvt to convert an integer to floating point.
  • vmov.f32 s0, #1.5 only takes constants of the form ±(16 to 31)/16 × 2n with n from −3 to 4, such as 0.5, 1.0, 1.5, 2.75 or 10.0. For any other value use .float or .double data and vldr.
  • vldr/vstr take [Rn] or [Rn, #offset] with an offset that is a multiple of 4 up to ±1020, or a label within 1020 bytes. For data further away, use ldr r0, =label and then vldr s0, [r0]. vldm/vstm (ia or db, optionally with !) and vpush/vpop take a list of consecutive registers: vpush {d8-d15}. All VFP loads and stores need a word-aligned address.
  • A compare sets the N, Z, C and V flags in the FPSCR, not in the core. Copy them with vmrs APSR_nzcv, fpscr (or fmstat) before a conditional branch: then blt, beq, bgt and so on work as for integers, and bvs means unordered (a NaN was compared).
  • vcvt.s32.f32 s0, s1 converts to an integer rounding toward zero, as C does; vcvtr uses the FPSCR rounding mode. Out-of-range values saturate and NaN gives 0. vcvt.f64.f32 and vcvt.f32.f64 change precision. With #fbits it converts to or from fixed point in place: vcvt.s32.f32 s0, s0, #16. vcvtb/vcvtt convert to and from half precision in the bottom or top half of an s register.
  • Arithmetic is exact IEEE 754 with the rounding mode set in FPSCR (round to nearest by default). The FPSCR keeps cumulative exception flags: IOC (invalid, e.g. 0/0), DZC (division by zero), OFC (overflow), UFC (underflow), IXC (inexact) and IDC (input denormal). Invalid operations give the default NaN 0x7FC00000. FZ (flush to zero) and DN (default NaN) work when set with vmsr.
  • On the Memory tab, the Floats button adds a column showing each word as a float, or each 8-byte-aligned pair of words as a double.
  • mrs r0, apsr copies the core N, Z, C and V flags into bits 31–28 of r0; msr APSR_nzcvq, r0 (or #imm) sets them.

Calling functions from C

Write the C prototype of a function in a comment that starts with @ C:, then open the C Call tab on the right.

@ C: extern int sum_array(const int *a, int n);
        .global sum_array
sum_array:
        mov     r2, #0
1:      ldr     r3, [r0], #4
        add     r2, r2, r3
        subs    r1, r1, #1
        bne     1b
        mov     r0, r2
        bx      lr
  1. Choose the function and type an argument for each parameter. The panel shows where each one goes.
  2. Call runs the function until it returns. Step into stops at its first instruction; continue with Step or Run.
  3. The result shows the return value, any arrays before and after the call, and calling-convention problems.

Saving arguments as cases

Each function can keep several named sets of arguments, called cases. The Case row under Function picks one. Type a name and press Save as to keep the current arguments as a new case. Like Save As in an editor, the new case is then the one you edit. Delete removes the case shown.

Cases are saved with the source: saving prog.s also writes prog.ccall beside it, and opening prog.s loads prog.ccall if it is there. Changing an argument marks the file unsaved. A .ccall file is short, readable JSON, so it can be edited by hand or handed out with the .s.

Arrays of structs

Declare a struct in an @ C: comment, before or after the prototypes that use it, then pass a pointer to an array of them. A declaration may continue over several @ C: lines.

@ C: struct student { char name[16]; int score; double gpa; };
@ C: typedef struct __attribute__((packed)) { char tag; int value; } item_t;
@ C: extern void curve(struct student *s, int n, int bonus);
@ C: extern int sum_values(const item_t *items, int n);
  • Members are laid out as gcc does on ARM: each at a multiple of its own size, double and long long at a multiple of 8, and the struct padded to a multiple of its largest member. __attribute__((packed)), before or after the braces, removes all padding. The panel shows each struct's layout, e.g. struct student: 32 bytes, aligned to 8: char name[16] at 0, int score at 16, double gpa at 24.
  • Enter the array as a C initializer: {{"Ann", 90, 3.5}, {"Bob", 75, 2.8}}. Members left out are zero; a char array member takes a string, other array members {1, 2, 3}. [n] after it makes room for n structs.
  • Members can be numbers, _Bool, pointers (given as addresses) and fixed arrays. Structs inside structs, unions, and structs passed or returned by value are not supported.
  • The result shows a row per struct and a column per member; changed members show before → after. An expected value such as {{"Ann", 95}, {"Bob", 80}} checks only the members it gives.
  • A packed struct's members can be at odd addresses: ldr r3, [r0, #1] loads one, as unaligned loads work on ARMv7 Linux (unless Strict Alignment is on).

Expected results

A case can also say what the call should produce, so it checks itself. Type the expected value in Expected … result below the arguments, and for a pointer that is not const, its expected contents in the box under its argument: {0, 1, 4, 9}, or "text" for a char buffer. Only the elements you list are compared, from the first. After each call the result shows ✔ or ✘ for every check, with the expected and actual values, and History counts how many passed.

  • Integer, pointer and _Bool results must match exactly. A pointer can be expected as a label, an address or NULL.
  • float and double results match if they are within a relative 10−6 (double: 10−12) of the expected value, so ordinary rounding differences pass.
  • Expectations are part of the case and are saved in the .ccall file.

How arguments are passed

  • Integer and pointer arguments go in r0–r3, the rest on the stack at [sp], [sp, #4], … SP is a multiple of 8 at the call.
  • As on armv7hf Linux (the hard-float convention), float arguments go in s0–s15 and double arguments in d0–d7, separately from the integers. A float can fill a gap left by a double: f(float a, double b, float c) uses s0, d1 and s1. When they run out, the rest go on the stack.
  • char and short arguments are sign- or zero-extended to 32 bits. Plain char is unsigned on ARM.
  • A long long (int64_t, uint64_t) takes a pair of registers starting at an even one, low word first: r0 and r1, or r2 and r3. f(int a, long long b) leaves r1 unused and puts b in r2 and r3. On the stack it takes 8 bytes at a multiple of 8. A 64-bit result comes back in r0 (low) and r1 (high).
  • The result is returned in r0, or s0 for float and d0 for double. A function returning char, short or _Bool must extend it to 32 bits itself.
  • The function must leave r4–r11, SP and s16–s31 (d8–d15) as it found them, and must not change the FPSCR rounding mode.

For example, to show strcat, give dest the string "Hello, " [32] and src the string world, and expect dest to hold "Hello, world". Char buffers are also shown as text before and after the call.

@ C: extern char *my_strcat(char *dest, const char *src);
        .global my_strcat
my_strcat:
        mov     r2, r0              @ keep dest to return it
1:      ldrb    r3, [r2]            @ find the end of dest
        cmp     r3, #0
        addne   r2, r2, #1
        bne     1b
2:      ldrb    r3, [r1], #1        @ copy src, including its 0
        strb    r3, [r2], #1
        cmp     r3, #0
        bne     2b
        bx      lr

Arrays and strings are placed in memory starting at 0x10000000.

Checks after the call

  • r4–r11 or SP not preserved. They start with recognisable values 0xC0DE0004–0xC0DE000B.
  • s16–s31 not preserved (they start as 16.0 to 31.0), or the FPSCR rounding mode, FZ or DN changed.
  • A char, short or _Bool result that is not properly extended.
  • Data changed through a const pointer.
  • The function is not declared .global.
  • The function never returned: it ran off the end of the code, or looped until the step limit.

Not supported

  • NEON (Advanced SIMD) vector instructions: floating point is scalar VFP only. VFP instructions take one cycle each in the cycle count.
  • Thumb code, blx, and branching with bx to an odd address.
  • System calls (svc): programs end by returning or running off the end.
  • Exclusive loads and stores (ldrex, strex), and saturating and SIMD instructions.
  • Macros, .include and conditional assembly (.if).
  • In C calls: long double, structs, variadic functions and function pointers.
